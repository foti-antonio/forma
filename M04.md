# M04 — Local Git Integration

Implementation and verification record, 2026-10-15. Hosted verification
is being completed on `milestone/m04-local-git`; results below record executed
checks only. No release is published.

## Implemented

- Native folder selection validates normal repositories, linked worktrees and
  bare repositories in Rust before saving. One repository is active per project;
  reconnect/disconnect retains historical links. Name, canonical path and branch
  appear in project details.
- Dedicated read-only local libgit2 reader, service validation and parameterized
  SQLite repository, behind feature store → typed IPC → blocking Rust commands.
  No shell, network Git or repository mutation APIs; capabilities are unchanged.
- Project Git panel with staged/unstaged/untracked/conflict counts, local branch
  search and latest commit metadata, bounded HEAD history, manual refresh,
  detached/unborn/bare/empty states and recoverable repository errors.
- Issue Git activity with multiple branch/commit links, exact issue-identifier
  suggestions and mandatory review/confirmation. Immutable commit snapshots
  retain historical branch names even after deletion, rename or disconnect.
- Append-only migration 004 adds repository and link tables, scoped constraints
  and indexes. Migrations 001–003 remain unchanged. Existing user data survives.
- Backup format 2/schema 4 includes associations. Exact-schema M03 format 1/
  schema 3 snapshots upgrade in private staging. All imported paths are disabled
  until native folder selection authorizes access; missing paths do not block
  restore. Recovery and replacement confirmation remain intact.
- Existing List/Board behavior and keyboard shortcuts remain available. Git
  sections load on expansion and do not poll. React renders untrusted metadata
  as text; error messages never expose libgit2 configuration/credentials.

See [GIT](docs/GIT.md) for policies, security boundaries, bounds and count
semantics; [BACKUP](docs/BACKUP.md) for compatibility and recovery.

## Performance

Debug Rust on this Linux host, local temporary filesystem, real libgit2 repository:
501 commits, 1,001 branches and 10,000 individual untracked files. One connection
validation and five warm reads, no watcher or polling. These are service timings,
not UI frame-rate or production-machine guarantees.

| Operation                                    | Measured elapsed |
| -------------------------------------------- | ---------------- |
| Connect including status and HEAD validation | 31.584 ms        |
| Overview: full status plus first 20 commits  | 30.273–30.709 ms |
| Filter 1,001 branches (`099`), bounded page  | 7.187–7.392 ms   |

Status explicitly avoids index writes and rename detection. Branch output is
capped at 100/request (UI 25), history at 100/request (UI 20), offsets at 10,000,
branch scan at 10,000, messages at 4,000 characters, authors at 200, and links at
200/issue. Large status scans still allocate a full libgit2 status list and hold
the shared database mutex. There is no cancellation or hard scan-time guarantee;
independent Git workers and resource limits should be driven by larger real data.

## Limitations and M05 recommendations

One active repository/project; prior records remain for provenance, without a
historical repository management UI. Links are immutable snapshots rather than
live branch tracking; renamed/deleted branch names do not silently retarget.
Suggestions inspect only 25 branches and 20 recent HEAD commits; manual exact
branch/full-hash linking covers other local work. SHA-256 repositories, remote
branches, diffs, write operations and network Git are outside this milestone.

Use a single Forma instance during restore. Backups remain unencrypted and do
not contain Git objects/files. Native folder selection is required after restore,
including recovery. Status may block other database operations behind the mutex
on unusually large repositories. Count categories can overlap; submodule content
and rename detection are deliberately excluded.

M05 should prioritize native Windows/macOS interactive testing, realistic large
repository measurement, cancellation/dedicated Git workers and historical-link
navigation. Any write or network Git requires a separate security/UX design.
Cloud sync, authentication and AI agents remain out of scope.
