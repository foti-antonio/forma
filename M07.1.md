# M07.1 — Release Hardening

Verification date: **2026-10-16 (Europe/Rome)**. Candidate **v0.1.0-beta.1**.
Branch: `milestone/m07.1-release-hardening`. Parent documentation commit `2f14c18`;
verified M07 source `7f9f0aa90669f9e9d961fc396b242e7b4e832eb6`.

This milestone resolves or characterizes release blockers; it does not authorize
public distribution. No merge, tag, release, credentials or security bypass was
created. Native trust and remaining manual acceptance gates remain mandatory.

## Changes implemented

- Raised both macOS deployment floors to **15.0** in Tauri packaging and CI.
  Added package Info.plist identifier/version/minimum checks and a regression
  guard against accidental deployment-floor drift. Older macOS is unsupported.
- Made Windows Evergreen WebView2 bootstrap provisioning explicit. Added runtime
  registry diagnostics and native UI Automation workspace creation/restart/close.
- Added Linux AT-SPI workspace creation/restart and ordinary EWMH window closing
  for installed DEB and FUSE-free AppImage on hosted Ubuntu with matching packages.
  Package diagnostics retain only sample process logs and host/journal metadata,
  never databases, private backups or process memory dumps.
- Added public macOS AX workspace creation/restart and native export-dialog
  cancellation with explicit unavailable status when runner TCC
  authorization is absent. It never prompts for access or edits TCC. DMGs are
  mounted/copied, metadata checked, launched twice and terminated through
  NSRunningApplication; this is distinct from Finder/Gatekeeper acceptance.
- Added separate fresh beta installs and isolated Windows NSIS/MSI upgrades
  from verified internal `0.1.0` packages
  (M06.1 run `38793649445`) before restart and uninstall/data-retention checks.
- Hardened signing preflight to require independent reviewers, prevention of
  self-review and only the exact approved tag, with rejection regression tests.
  Enabled RFC3161 timestamping explicitly and extended Windows trust checks to
  the application executable, timestamps and expected signer identity.
- Fixed Unix executable validation accepting setuid/setgid mode bits. The common
  validator now rejects these bits for provider and independent-test selection
  and revalidation. A regression covers setuid, setgid, both and writable modes.
- Documented owner certificate acquisition/configuration, the limitations of
  exportable PFX on modern hardware-backed signing, reviewer/tag rules, backup
  privacy/retention and support boundaries. No product feature or migration added.

Tailwind **4.3.3**; Rust GTK/WebKit bindings **0.18.2 / 2.0.2**. Binding/API version
numbers are not the native WebKit engine version or an OS compatibility claim.

frontend support guarantee. [Tailwind 4](https://tailwindcss.com/docs/compatibility)

lists older macOS Safari availability; that is insufficient evidence of Forma's
WKWebView compatibility on those OSes. We deliberately choose the executed macOS
15 runner family for the candidate floor, rather than infer support from Safari
updates or Tauri's historical packaging default. macOS 15.0 specifically and
older point releases are not independently executed by a `macos-15` label.

historical WebKit subprocess core records remain (PIDs 338852, 343149, 344595,
351861, 353563; three SIGSEGV, two SIGABRT). The first crash's stack passes through
libc, host `dri_gbm.so`, `libgbm.so.1`, extracted WebKit and `exit()`. A worker
thread includes host Mesa EGL during teardown. Numerous frames remain unresolved.
No Forma Rust frame establishes an application fault. Graphics/WebKit shutdown
interaction in this mixed runtime is an inference, not a proven upstream cause.
`free -h` showed 8.9 GiB available; the inspected kernel journal window contained
no OOM match. No new memory dump was extracted or uploaded.

`pkg-config --modversion webkit2gtk-4.1` and `pacman -Q webkit2gtk-4.1` confirmed
no installed WebKitGTK. `sudo -n true` required a password. Therefore a normally
installed matching-library reproduction is unavailable on this local host;
installing extracted libraries is not represented as that reproduction. Hosted
Ubuntu package tests provide the feasible distribution-matched comparison.

native agent/beta suite **reproduced a sixth WebKit SIGSEGV**: PID **402253**,
**2026-10-16 00:23:22 CEST**, exactly the smoke log's final modification time.

`libgbm.so.1`, extracted WebKit and libc `exit()` teardown. All-thread metadata
is retained locally in `core-402253.log`; no new memory dump was extracted.

## Security, privacy and signing readiness

Reviewed capabilities, CSP, executable identity, preview/approval, process
supervision, independent-test authorization and backup staging/retention.
`main` permissions remain empty. Provider/test launch uses canonical executable
identity, digest/mode revalidation and an environment allowlist. Explicit
single-use previews, queue dispatch and test approvals remain in place. Unix
process groups/watchdogs and Windows kill-on-close jobs remain defense in depth.
Same-user replacement races, escaped descendants and missing hard resource/network
quotas remain documented. **Worktrees are not OS security sandboxes**; selected
providers and tests can access the host as the user. No isolation claim is added.

Backup staging uses private temporary files and recovery snapshots. Backups and
logs can contain sensitive tasks/code and are unencrypted; redaction is heuristic.
Exports/recovery copies have no automatic pruning. Workspace deletion does not
erase prior exports. Restore continues stripping executable/repository/worktree
permissions, invalidating approvals and interrupting unfinished execution.
`git diff` against verified M07 found no migration or dependency-lock changes.

Read-only GitHub audit: repository visibility **PUBLIC**, viewer permission
ADMIN; environments `total_count: 0`, repository secrets `[]`,
rulesets `[]`. No secret values were accessed. The prepared signing workflow is
statically validated and regression tested, **not executed with trusted signing**.
Exact owner instructions are in [RELEASING](docs/RELEASING.md#acquiring-and-configuring-signing-credentials).
Windows hardware/cloud signing needs a reviewed integration if a lawful
exportable PFX is unavailable; the current import path cannot be assumed usable
for newly issued HSM certificates. Apple requires Developer ID Application and
notarization credentials. Administrator bypass and tag creation rules need owner
review in addition to the automated reviewer/exact-tag environment checks.

## Remaining blockers and exact next release steps

1. Use the recorded source/artifact inventory for review. Rebuild from that
   exact source and lockfiles when needed, then repeat the checksum and native
   acceptance gates. Failed/incomplete candidate sets are not distributable.
   CI archives and the pinned M06.1 upgrade baseline expire after 30 days; preserve
   reviewed baseline bytes/checksums in approved storage before expiration. If the
   baseline expires, rebuild the verified M06.1 source, review its new hashes and
   update the workflow reference/checksums; never silently skip upgrade tests.
2. Owner provisions `release-signing`, an independent eligible reviewer, no
   self-review/admin bypass, exact version **Tag** policy and an active tag ruleset
   restricting creation/update/deletion. No such protection currently exists.
3. Owner acquires authorized signing credentials/services as described in
   RELEASING. Configure environment secrets only after source/workflow review.
   Implement/review hardware/cloud Windows signing if required by the issuer.
4. Complete clean Windows 10/11 NSIS/MSI and Intel/Apple Silicon macOS acceptance:
   install, full application UI, native backup/folder/executable dialogs, restart,
   real upgrade, uninstall with data retention, and ordinary platform trust.
   Include installed/missing WebView2 and unavailable-network installer behavior
   on disposable Windows machines; those runtime bootstrap cases are unverified.
   Preserve quarantine and security policy. Record exact OS/package SHA-256.
5. Complete clean Ubuntu 24.04 desktop AppImage/DEB rendering, GPU/Wayland shutdown
   and durability testing, plus intended distribution/GPU coverage. Headless
   software rendering cannot clear the local hardware-specific crash question.
6. Review the exact candidate SHA and version, remaining host-execution/privacy
   limits and all acceptance evidence. Obtain explicit authorization before
   creating/pushing `v0.1.0-beta.1`; this milestone creates no tag.
7. The approved tag path must pass protection, all regressions, trusted Windows
   executable/installer signatures, accepted Apple app/DMG notarization and
   stapling, then create only a draft prerelease. Verify the new signed hashes
   and downloaded native trust behavior. Unsigned candidate hashes will differ.
8. Obtain separate explicit approval before publishing the reviewed draft or
   merging to main. Neither a branch push nor green CI authorizes those actions.
