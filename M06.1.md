  `independently_approved_tests_capture_failure_cancel_limits_and_restore_trust`,
  and `interrupted_tests_and_restored_queue_never_resume_or_restore_authorizations`.

M06 exports format 4/schema 6 and accepts exact-schema M03 format 1/schema 3,
M04 format 2/schema 4 and M05 format 3/schema 5 backups, upgrading in private
staging. Older Forma versions cannot restore M06 exports. Restored repository,
provider/test executable and worktree authorization is removed; unfinished runs
are interrupted and unused approvals invalidated. These are automated SQLite
regressions, not a claim of a real power-loss experiment.

## Failures and fixes

- Initial [run 38789161858](https://github.com/foti-antonio/forma/actions/runs/38789161858)
  stopped Windows at `pnpm format:check`: the checkout converted text files to
  CRLF, producing 67 formatter warnings. Commit
  `2f4c9f249135de96efbbd1f6c83c4169a024ff37` added `.gitattributes` with
  `* text=auto eol=lf`. A local `git -c core.autocrlf=true checkout-index --all`
  into a temporary prefix verified LF in 114 text files and byte-identical binary
  PNG/ICNS/ICO assets. The next hosted Windows formatting check passed.
- [Run 38789682338](https://github.com/foti-antonio/forma/actions/runs/38789682338)
  exposed a board focus race on macOS Apple Silicon. A delayed restoration frame
  stole focus after the user selected another card, causing the next keyboard
  move to target issue 2 instead of issue 1. A deterministic regression held the
  animation frame and reproduced the wrong focus before the fix. Commit
  `e240076ec89504f4713603870ec60a3baf6cb7c7` restores focus only while it remains on the original element or the
  document body. The new regression and all 49 frontend tests passed locally;
  lint, typecheck and production frontend build also passed. Existing assertions
  and security checks were retained, with no retries masking the failure.

- The same second run reached Windows Rust/IPC tests and failed
  `interrupted_cleanup_recovers_registration_without_force_removal` with
  “Registered worktree path changed.” Rust canonical paths retain a Windows
  verbatim prefix while libgit2 normalizes the registered path. Commit `861d07181b268e71930f1464799e0a75fc5e92bf` now
  verifies the canonical existing parent and exact UUID leaf because the leaf
  has already been removed. The regression additionally rejects changed parent
  directories and run names, retains registration on rejection and checks that
  successful recovery retains the branch. No force-removal or authorization
  bypass was introduced.
- Dependency source inspection (`tauri` → `dirs` → `SHGetKnownFolderPath`)
  established that Windows ignores process `APPDATA` overrides for its app-data
  location. Commit `abec7b3a8ff9485a66114ac8b915bf9da48f4040` corrected the
  smoke harness to require an ephemeral GitHub-hosted runner, resolve the actual
  OS roaming folder and reject pre-existing Forma data. Production app-data
  resolution remains unchanged. The Linux smoke and Python compilation passed
  after this harness correction.
- Runs [38790193363](https://github.com/foti-antonio/forma/actions/runs/38790193363)
  and [38790643823](https://github.com/foti-antonio/forma/actions/runs/38790643823)
  were cancelled as superseded after the Windows cleanup defect was confirmed.
  They are not counted as successful complete matrices.

- [Run 38791234530](https://github.com/foti-antonio/forma/actions/runs/38791234530)
  passed Windows tests and Clippy and generated NSIS/MSI, but the initialization
  smoke failed with `unknown path`. The harness still replaced Windows profile
  environment variables; the native known-folder API could not resolve app data.
  The failure also exposed WebView2 descendants retaining temporary files after
  the Forma process exited. Commit `435dca825586121dd433188a846fa615da3f1f5b`
  preserves the Windows hosted profile environment and uses PID-scoped
  `taskkill /T /F` for live smoke process cleanup. The fresh hosted directory
  precondition, schema/integrity assertions and live-process checks remain.
  Python compilation and the Linux package smoke passed again. No application
  persistence override or new Tauri capability was introduced.

## Verification boundaries and M07 readiness

The verification levels are distinct:

| Platform/package    | Compilation and packaging  | Process initialization                                                                  | Installer interaction                                                            |
| ------------------- | -------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Linux x86_64        | AppImage and deb generated | Extracted deb launched under D-Bus/Xvfb; schema 6 and integrity checked                 | No deb installation and no AppImage execution or FUSE check                      |
| Windows x86_64      | NSIS and MSI generated     | Installed NSIS app launched in fresh hosted OS app data; schema 6 and integrity checked | NSIS silent installation passed; no interactive NSIS/MSI verification            |
| macOS Intel         | App and DMG generated      | DMG mounted, app copied and launched; schema 6 and integrity checked                    | No Finder drag-to-Applications, Gatekeeper or interactive installer verification |
| macOS Apple Silicon | App and DMG generated      | DMG mounted, app copied and launched; schema 6 and integrity checked                    | No Finder drag-to-Applications, Gatekeeper or interactive installer verification |

Interactive installer and rendered UI checks were not executed by this gate on
any platform. Initialization proves a live process and an intact database after
the smoke waiting period; it does not prove correct rendering, every user flow,
packaged restart behavior or a graceful shutdown. AppImage and MSI are build
artifacts whose execution/installation remains unverified.

macOS CI uses ad-hoc signing, not a Developer ID identity. Windows packages are
unsigned. No Authenticode trust, Apple notarization or clean-machine trust prompt
verification is claimed. No release was published and no updater was added.

M07 readiness: the automated cross-platform build/package/initialization gate
is complete with no unresolved CI blocker. M07 release preparation can proceed;
public distribution is not yet verified ready. Public release work still needs clean-machine interactive installation, rendering and key workflows
on each architecture, protected Windows signing and macOS Developer ID signing
and notarization. Real authenticated Claude and concurrent real-provider
completion remain unverified by this gate. Worktrees are not OS sandboxes;
provider/test processes retain the current user's privileges and there are no
hard CPU/RAM/disk quotas. Existing M06 security/resource limitations remain open
release-planning inputs. No new product feature is part of this gate.
