# M02 — Issue Management

Implemented locally on 2026-10-15. The verification record below distinguishes
service, IPC transport and native UI coverage. Windows and macOS have not been
built or run in this environment.

## Implemented features

- Project detail with issue list, literal search (including identifiers), status
  and priority filters, five deterministic sort orders, archive view, issue/done
  counters, bounded pagination, loading/error/retry and empty states. Project
  settings and all M01 workspace/project workflows remain available.
- Issue create/read/update/delete, Markdown description and safe preview, all five
  statuses/priorities, due date, persistent manual order, timestamps, archive and
  restore. Stable `F<project key>-<issue number>` identifiers survive rename,
  editing, archival and restart; deleted numbers are never reused.
- Single-level subtasks with same-project parents, parent search/pagination,
  child lists inside parent editors, parent reassignment and child creation.
  Rust and SQLite reject self-parenting, cycles, deep nesting and project moves.
  Parent deletion promotes children, preserving their content and recording the
  relationship change. Archival affects the selected issue only.
- Workspace label CRUD with names/colors and duplicate-name validation, issue
  assignment, same-workspace validation, and unique assignment constraints.
  Deletion confirms workspace-wide removal from issues.
- Paginated per-issue activity. Issue mutations, label assignment changes,
  numbering and their events commit atomically. Activity summaries contain action
  or changed-field names rather than issue titles/descriptions/previous values.
- Keyboard-accessible Radix dialogs, focus-managed deletion/discard prompts,
  visible labels, retained drafts after save errors, `N`, `/`, and Ctrl/⌘+Enter.
  Dirty drafts prevent accidental navigation to children or archive actions.
- Append-only migration 002; migration 001 remains unchanged. Populated v1
  upgrade preserves projects, issue UUIDs/descriptions, labels/assignments and
  existing activity. Failed upgrades roll back both schema changes and version.
- Rust service/database tests, frontend component/store tests, an opt-in Tauri
  command transport test, and an opt-in Linux native form/restart smoke script.
- README, architecture, roadmap, and a concrete [issue domain spec](docs/ISSUES.md).

## Architecture decisions

The existing UI → Zustand → typed IPC → Rust command → service → repository /
SQLite boundary remains. Rust owns all persistence. New issue modules keep the
feature out of M01's workspace/project code. No new Tauri permissions, network
clients, shell/filesystem plugins, authentication, cloud services or AI tools
were added. There is no Kanban board in M02.

Migration 002 uses ALTER TABLE to preserve legacy rows/foreign keys. Project
keys use SQLite AUTOINCREMENT; issue counters live on projects and increment
inside issue creation transactions. Database checks/indexes/triggers enforce
supported priorities, ordering, unique numbers, hierarchy and label workspace
joins. Service validation supplies actionable structured errors.

The issue store serializes writes and uses request generations to discard stale
project/filter responses. Read and mutation errors are separate: if a committed
save's refresh fails, the save still succeeds and the list offers Retry, avoiding
duplicate issue creation. React owns editor drafts; Rust responses remain
canonical. List, parent chooser, subtasks and activity all have bounded queries.
The current synchronous mutex/connection is retained for this local workload.

CommonMark uses react-markdown without raw HTML or extra plugins. Links are text
and images display alt text; neither navigates the WebView nor fetches remote
content. The upstream [react-markdown documentation](https://github.com/remarkjs/react-markdown)
was checked while selecting the renderer. Data stays in the existing app-data
SQLite location. Appearance is still the only browser-storage preference.

### Temporary Linux prerequisites

The system still lacks WebKitGTK 4.1. To run the full desktop checks without
changing installed packages, used `pacman -Sp --print-format '%l'
webkit2gtk-4.1`, `curl -fLsS --retry 2`, and `tar -xf` to extract WebKit and its
missing dependencies into `/tmp/forma-m02-sysroot`. An initial urllib download
received HTTP 403; curl downloads succeeded. Desktop commands above used:

```sh
PKG_CONFIG_PATH=/tmp/forma-m02-sysroot/usr/lib/pkgconfig
LD_LIBRARY_PATH=/tmp/forma-m02-sysroot/usr/lib
LIBRARY_PATH=/tmp/forma-m02-sysroot/usr/lib
```

For actual runtime only, the two compiled helper-directory strings in this
**temporary third-party WebKit library** were redirected to `/tmp/fm2`, a symlink
to the extracted WebKit helper directory. This workaround changed only temporary dependency files; it did not alter
application source, system libraries or WebKit sandbox settings. Native launches used temporary
XDG_DATA_HOME/XDG_CONFIG_HOME/XDG_CACHE_HOME paths, never the user's real Forma DB.
Install README's normal system prerequisites for ordinary development.

### Native Linux UI and restart verification

The final `scripts/native-smoke.py` run passed against the actual built Linux
WebView application. It used wtype input through the real forms and shortcuts;
all SQLite queries were read-only assertions, with no mock persistence or seeded
application records. It performed:

1. Created **smoke studio** and **smoke engine** through workspace/project forms.
2. Opened the project's issue list, pressed `N`, and saved **parent task** using
   Ctrl+Enter; allocated identifier **F1-1**.
3. Created the workspace label **smoke label** through its dialog.
4. Edited the parent title to **parent task edited** and description to
   `**verified markdown**` through the issue editor.
5. Used the parent's **Add subtask** action to create **child task** (**F1-2**)
   and selected **smoke label** in the child form.
6. Terminated the native process and started a new process with the same isolated
   app-data directory. Opened the project, searched for the child, and opened its
   editor. The rendered list and editor retained titles, relation and label.
7. Asserted the saved hierarchy/label rows and schema version 2;
   `PRAGMA integrity_check` returned `ok`, and `PRAGMA foreign_key_check`
   returned no violations.

Successful run artifacts: `/tmp/forma-m02-smoke-ijwzfyes/`, including
`restarted-list.png`, `restarted-child.png`, `native.log`, and the isolated SQLite
database under `data/dev.forma.desktop/`. Temporary artifacts are not committed.
The script terminates the process on completion or failure and refuses to type
when another application is focused.

Initial script runs failed on an OCR string, native text-replacement assumptions,
and tab counts through WebKitGTK's segmented date control. The final script uses
visible body text for waits, appends a title edit, and accounts for month/day/year
tab stops. Those failed runs were harness diagnostics; their temporary data was
not reused as successful evidence. An earlier manual native run also created a
workspace/project/issue, but the final automated run is the restart evidence.

## Remaining limitations and unverified platforms

- Windows NSIS/MSI and Windows runtime are unverified here. Intel macOS and Apple
  Silicon macOS app/DMG builds and runtimes are also unverified here.
- Linux debug executable build is verified. Optimized release bundles, portable
  AppImage/deb installation, signing/notarization and remote CI/release publishing
  were not executed for M02. M01 package results are historical, not M02 evidence.
- The native smoke is specific to a Linux Hyprland session with wtype/grim/
  tesseract, requires focus and has OCR dependencies; it is not cross-platform
  automation. Component, real-service and IPC coverage exercise additional paths.
- Offset pages can shift when data changes between requests. SQLite case folding
  for search/duplicate label names is ASCII; full Unicode search is future work.
- Single-level hierarchy, explicit numeric order and per-issue archival are
  deliberate. There is no bulk edit, drag-and-drop, label filter or attachment UI.
- CommonMark preview has no GFM tables/task-checkbox extensions, active links or
  remote images. Markdown source remains editable and preserved verbatim.
- One synchronous database connection and manually maintained IPC types remain.
  Large datasets should motivate background work/generated contracts and measured
  query optimization; no speculative abstractions were added.
- Data remains unencrypted and local to one device. Export/backup/recovery UI,
  synchronization, authentication and AI integration are absent.
