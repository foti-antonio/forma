# Optional private beta feedback

Submit only if you choose, via the coordinator's agreed private channel. No real
name, email, employer, demographics or repository identity is required. Do not
include credentials, private code/repositories, raw backups/databases, agent
prompts/transcripts or sensitive logs. Screenshots are optional and must contain
sample data only. Bug details belong in the [bug form](BETA-REPORT.md).

```text
Tester alias (optional):
Forma version / platform family + architecture:
Acceptance rows attempted (IDs only):
Most useful workflow, using a generic description:
What was confusing or difficult?
Ease of setup: easy / manageable / difficult / blocked / not attempted
Ease of issue/Board work: easy / manageable / difficult / not attempted
Did approval and cancellation consequences feel clear? Yes / No / Not attempted
Did backup/restore and data retention consequences feel clear? Yes / No / Not attempted
One improvement you would prioritize:
Any accessibility barrier (no medical/personal information needed):
Related sanitized bug IDs, if any:
May the coordinator retain this sanitized response through beta closure? Yes / No
May an anonymized quotation be shared publicly later? No (default) / Yes
```

Participation and each question are optional. The coordinator must set and tell
participants the test window, feedback location and retention deadline before
opt-in. Proposed default: delete private roster/contact records and raw feedback
within 30 days of beta closure; agree the exact deadline before enrollment.
Use alias-based summaries for triage, and publish no quotes without explicit
consent. Keep only sanitized technical blocker/acceptance evidence after closure.
Withdraw through the same channel; remove linkable private responses on request
and explain that already public, voluntarily filed issues cannot guarantee erasure
of third-party copies. There is no in-app telemetry or automatic feedback upload.
