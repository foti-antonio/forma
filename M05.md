# M05 — AI Agent Integration

Implemented on 2026-10-15. Forma now supports explicitly approved local coding
agent tasks in dedicated Git worktrees, with persistent history and human review.
No release, push, merge or automatic integration is performed by this feature.

## Delivered

- Rust provider abstraction with Codex and Claude adapters, informational PATH
  discovery, native executable authorization, canonical paths, SHA-256 identity
  checks, version/help capability checks and fixed noninteractive argument arrays.
- Agent settings for preferred provider, executable, runtime, bounded output and
  permission policy. Existing provider authentication is used; Forma does not
  collect credentials or store secrets in settings.
- Saved-issue AI Agent section, exact task prompt preview and a single-use,
  five-minute approval token bound to issue/settings/executable/repository HEAD.
  Claude additionally requires acknowledging the lack of whole-process OS
  filesystem isolation. No background execution or automatic elevation exists.
- Narrow libgit2 worktree creation in app-data with UUID branches, no overwrite,
  repository authorization checks and conservative rejection of dirty, unborn,
  detached, bare, submodule, tracked-symlink and in-progress Git states. One active
  global run; a SQLite unique index also prevents duplicate active issue runs.
- Rust process-group/Windows-job supervision, bounded concurrent stdout/stderr
  readers, JSON progress, bounded redacted logs, cancellation, timeout, exit and
  failure handling. Unix pipe watchdogs and Windows kill-on-close jobs protect
  against ordinary owner exit; an exclusive app-data lock prevents two owners.
- Append-only migration 005 stores settings, run UUID/issue/provider/repository,
  worktree/base/branch, Queued/Running/Completed/Failed/Cancelled/Interrupted
  lifecycle, UTC timestamps, exit result/logs and review decision. Restart marks
  incomplete runs Interrupted and never resumes automatically.
- Global runs/settings dialog and issue-scoped paginated history. Runs show the
  issue identifier/title, elapsed time, recent structured event types, bounded
  text logs and cancellation. Results show changed files, bounded diffs, counts,
  execution/test-report context, folder opening and explicit accept/reject for
  manual integration. No agent HTML or Markdown executes.
- Backup format 3/schema 5 includes metadata/settings/bounded logs, excludes
  credentials/repository contents/worktrees, upgrades exact validated M03/M04
  snapshots in staging and removes imported executable/repository/worktree path
  authorization. Restore and data deletion are blocked during active execution.
- Updated README, architecture, backup and roadmap documentation, plus
  [AGENTS-INTEGRATION](docs/AGENTS-INTEGRATION.md). Existing CI jobs are preserved.

## Security and regression evidence

Backend tests exercise untrusted issue/repository instructions, shell/argument
injection strings, executable spoofing after authorization, task changes after
preview, dirty/missing repositories, symlink roots/retained worktrees/tracked
files, namespace-induced branch failure and worktree-registration failure with
partial branch retention, process exit 7, concurrent-run
rejection, cancellation, ordinary descendant termination, timeout, output flood,
overlong lines, secret/private-key redaction, owner-pipe EOF, interrupted restart,
review persistence, schema-5 rollback/retry and M03/M04 staged backup upgrade.
Backup restoration disables imported path access, including executable digests,
reapplies log redaction and enforces byte-based output bounds.
A long help-output fixture guards against losing capability flags after exit.

The real Tauri IPC test covers native-authorized fixture results, provider reads,
preferences, preview, approval refusal, start, bounded history, result diff,
review decision and terminal cancellation through production command handlers.
It uses a Tauri test runtime and real SQLite, not a native WebView.
Frontend tests verify inert prompt/output/diff rendering, no start before approval,
separate Claude consent, actionable errors, cancellation, settings and review.
Existing project, issue, label, board, Git and backup tests remain enabled.

Initial checks found and corrected a redaction false positive on
`--ask-for-approval`, loss of late help output, schema-fixture expectations and
native Git smoke keyboard positions after the new Agent section, and nested
dialog focus restoration. Native automation also needed OCR-stable text checks
and correctly grouped Ctrl+A key events. These failed
attempts were not counted as passes.

## Platform status and limitations

- Linux x86_64: real SQLite/libgit2, process groups/watchdog, simulated providers,
  real Codex completion, real Claude capability/failed launch, IPC transport and
  native debug build, native agent cancellation/crash recovery and review verified
  as recorded above.
- Windows x86_64: production code uses native `.exe` launching, Rust path APIs and
  kill-on-close Job Objects. Native process/worktree/UI/installer execution is
  **unverified locally**.
- macOS Intel and Apple Silicon: production code uses portable Rust paths,
  libgit2 and Unix process groups/watchdog. Native process/worktree/UI/DMG
  execution is **unverified locally**.
- Existing Linux/Windows/macOS CI jobs and packaging matrix are unchanged. No new
  hosted CI run, signed installer, release or packaging portability is claimed.

Worktrees share Git metadata and are not security sandboxes. Codex command
restrictions and Claude restricted file tools do not sandbox the whole provider
process. Prompt injection and heuristic secret redaction have limits. A malicious
trusted executable, same-user filesystem races, intentionally escaped process
groups, encoded secrets or resource-exhausting repository content require
stronger OS containment. libgit2 still allocates status/diff metadata. Diffs omit
large binary/ignored content; counts and displayed text have distinct bounds.
Provider-owned logs and network/telemetry policies remain provider-controlled.

There is no automatic worktree cleanup, merge, commit, push or rollback. Failed,
cancelled and rejected runs retain artifacts; imported historical paths stay
blocked for app access and can be inspected manually. Global concurrency is one.
Windows shell-wrapper installations are unsupported. Claude has no shell/test
tools in this policy, so independent testing is a manual review step.

## Recommended M06 scope

Verify authenticated Claude success and native Windows/macOS lifecycles and
installers. Add stronger whole-provider OS containment and brokered approvals,
independent test-result capture, measured large-repository resource limits and
explicit safe worktree retention/cleanup. Consider generated IPC contracts and
backup retention/encryption after defining key management.
