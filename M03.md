# M03 — Kanban & Productivity

Implemented locally on 2026-10-15. The record distinguishes actual Linux,
service and IPC execution from configured cross-platform CI. The existing M01/M02 implementation was preserved and included with M03 on a
separate milestone branch so the requested hosted CI can run.

## Implemented functionality

- Project **List / Board** views, remembered per project in SQLite. All M01/M02
  workspace/project/issue workflows and list pagination remain available.
- Five Kanban status columns with matching counts, empty/loading/error states,
  stable identifiers, title, priority, labels, due date and direct subtask
  completion. Enter opens the existing accessible issue editor.
- Keyboard movement using Alt + arrows, then dnd-kit pointer and keyboard sensors
  on dedicated handles. Space/arrows/Space performs drag/drop; Escape cancels.
  Visible focus, instructions, live announcements and focus restoration support
  keyboard use independently of pointer dragging.
- Shared AND filters for literal text/identifier search, status, priority, one
  workspace label, inclusive due-date range or undated work. Clear all filters
  resets the query. Board forces manual order; List retains all M02 sort orders.
- Independent replacement pages of 25 matches per column, retaining at most
  125 cards. Lists retain 25-row pages; Rust caps every issue query at 100.
- Atomic, scoped anchor movement with canonical refresh, rollback on failure and
  a single in-flight frontend mutation. Complete affected columns normalize
  deterministically; filtered-out cards keep relative order.
- Native-dialog SQLite snapshot export and validated, confirmed restore. Complete
  data and application preferences are included. A retained recovery copy precedes
  replacement; failed/incomplete SQLite copying rolls back. Connections reopen
  and frontend caches/navigation refresh after success.
- Appearance now persists in SQLite and participates in backup. First launch
  imports the M02 WebView preference; browser storage remains only a cache.
- Documentation: README, architecture, roadmap, issue policy and BACKUP.md.

## Architecture decisions

The existing UI → store → typed IPC → command → service → repository boundary
remains. Rust owns persistence. View preference reads/writes and Board movement
pass through the issue store module; backup controls use a dedicated small store.
Request generations discard obsolete project/filter responses.

Movement uses IMMEDIATE SQLite transactions, including across independent
connections. Before/after anchors identify real issues in the same project,
status and archive scope; null appends. Keyboard down and pointer drops on a later
sibling use after-anchors, avoiding accidental global append at a page boundary.
All hidden cards participate in canonical ordering. Changed issue status,
position, timestamp and activity commit together; rejected anchors and failed
activity inserts roll back normalization as well.

The store allows one move at a time. It refreshes after committed moves and after
failed moves, preserving authoritative data rather than maintaining optimistic
duplicate arrays. A committed write with a failed refresh remains committed and
shows a separate retryable read error, preserving M02 save semantics.

Issue queries and longer native backup commands run on Tauri’s async runtime
instead of the WebView event thread. The existing single mutex/connection remains;
there is no speculative storage rewrite. Native Rust rfd dialogs provide file
selection without exposing filesystem/dialog plugins or accepting paths from IPC.
Capabilities remain unchanged. No shell, network client, cloud sync,
authentication, AI agent, browser persistence or new external content is added.

The Board module is lazily loaded from bundled assets. Final production Vite
output is about 471 kB initial JavaScript plus a 51 kB Board chunk (before gzip);
this removed the initial single-chunk size warning while remaining fully offline.

Backup format 1 is a SQLite schema-3 snapshot with explicit format metadata.
Restore checks complete schema SQL, format/schema versions, integrity and foreign
keys in a pinned read transaction, then copies to private staging. It never
extracts archive paths. The selected source cannot change after validation.
Recovery export must succeed before replacement; SQLite’s backup destination
transaction supplies rollback and journal recovery. Reopen failure restores the
recovery snapshot. See docs/BACKUP.md for precise compatibility and recovery.

### Linux dependencies and diagnostics

The host lacks normal WebKitGTK 4.1 development packages. Desktop tests, Clippy
and builds used the already extracted M02 temporary sysroot:

```sh
PKG_CONFIG_PATH=/tmp/forma-m02-sysroot/usr/lib/pkgconfig
LD_LIBRARY_PATH=/tmp/forma-m02-sysroot/usr/lib
LIBRARY_PATH=/tmp/forma-m02-sysroot/usr/lib
```

The existing /tmp/fm2 helper-path workaround in that temporary third-party
WebKit library was reused. No system package, desktop configuration, application
database path or WebKit sandbox policy was changed. Native runs used temporary
XDG data/config/cache directories, never real user data.

An initial Rust run failed because the old schema assertion expected version 2;
it now expects 3 and the complete suite passes. Initial new frontend tests used
DOM assertion extensions absent from this repository; they now use the existing
Vitest assertions. Clippy flagged an allocated-path comparison, corrected with
an OsString sidecar comparison that also preserves non-UTF-8 paths.

The first native Board attempt reached all M02 forms but missed the card because
Board’s disabled sort changes tab order. The corrected run clears the search
after selecting Board and accounts for the skipped control. Its successful
restart artifacts, not the failed run, are the recorded evidence. An initial
large Vite chunk warning was resolved with a bundled lazy Board module.

explicit replacement confirmation, errors, unencrypted export messaging and
complete cache/app refresh. IPC tests additionally exercise movement with
after-anchors, combined filters, view/theme commands and confirmation validation.

## Performance measurements

Debug Rust service tests on this Linux host use real bundled SQLite in a temporary
WAL database. Seeded datasets contain mixed statuses, stable numbering, 500-byte
descriptions, due dates and priorities. Listing and text+priority filtering
average 30 requests; Board averages ten complete five-query loads of 25 cards
per column. Move timing is one complete transaction. These are service timings,
not frame-rate or production-machine guarantees.

| Dataset       | Seed     | List 25   | Text + priority filter | Board 5 × 25 | Move / normalize |
| ------------- | -------- | --------- | ---------------------- | ------------ | ---------------- |
| 1,000 issues  | 163 ms   | 2.555 ms  | 12.288 ms              | 8.973 ms     | 23.240 ms        |
| 10,000 issues | 1,915 ms | 13.938 ms | 124.444 ms             | 38.864 ms    | 281.770 ms       |

Before optimization, the 10k dataset measured 61.364 ms listing, 117.509 ms
text filtering, 103.746 ms Board loading and 2,725 ms movement. EXPLAIN showed
issues_status plus a temporary ORDER BY B-tree. The new covering board index
eliminates that sort. Empty-search short-circuiting avoids lowercasing every
description; materialized UPDATE FROM ranking avoids repeated correlated scans.
Text search remains linear and shows run-to-run variance; it was not accelerated
by the ordering index. No speculative search indexes were added.

## Platform verification and known limitations

- Linux: frontend production build, native debug executable, default/service/IPC
  Rust tests, Clippy and real WebView keyboard/restart smoke verified locally.
- Hosted CI execution is in progress on the separate milestone branch; final
  job results will be recorded after completion. Interactive native-dialog and
  installer/runtime behavior on Windows/macOS remains unverified locally.
- Optimized Linux bundles, portable AppImage/deb installation, signing,
  notarization and real power-loss testing were not executed for M03.
- Native smoke depends on Hyprland/wtype/grim/tesseract and guarded focus. It is
  opt-in and is not a cross-platform or headless CI substitute.
- One label filter at a time; status and priority are also single selections.
  Subtask hierarchy and M02 Markdown restrictions remain unchanged.
- Board pages replace rather than accumulate. Offset pages may shift during
  edits; navigate pages explicitly to reorder farther than the loaded cards.
  All statuses remain visible while filtered and a move may leave the filter.
- Literal substring search still scans matching project rows; no FTS yet.
  One serialized connection remains. Large text searches/moves show loading
  state while database work runs off the WebView thread.
- Backups are unencrypted, accept only format 1/schema 3, and require space for
  staging and recovery. Recovery files accumulate until manually removed.
  No archive extraction, arbitrary WebView paths, attachments or automatic
  scheduled backups exist. Use one Forma instance during restore.
