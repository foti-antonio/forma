# M01 — Foundation & Desktop App

Implemented and verified locally on 2026-10-15. This is a standalone pre-release
foundation. Windows/macOS builds and installer installation have not been run
locally; the workflow configuration is not evidence that remote jobs passed.

## Implemented

- Tauri 2 native host, React/Vite, strict TypeScript, Tailwind 4, local
  shadcn-style Button/Dialog primitives using Radix/CVA, Zustand, pnpm lockfile,
  ESLint, Prettier, Vitest, Rust formatting and Clippy checks.
- A desktop shell with workspace selection, sidebar project navigation, contextual
  title, project cards, archive, search, status filters, responsive layout, and
  light/dark/system appearance. Forms and controls are keyboard accessible.
  Radix dialogs manage focus and accessible descriptions.
- Workspace create, rename, confirmed deletion, persistent active selection,
  deterministic fallback when deleting the active workspace, and an onboarding
  empty state.
- Project create/edit, description, six icons, preset/custom hex color, four
  statuses, archive/restore, confirmed deletion, and workspace isolation.
- Rust-owned SQLite in the OS application-data directory. Version-1 transactional
  migration includes workspaces, projects, issues, labels, issue_labels,
  activity_events, and app_state. UUIDs, UTC timestamps, foreign keys, cascades,
  indexes, WAL, and atomic activity records are implemented.
- Typed IPC client, structured backend errors, backend input validation,
  serialized mutations, retryable reads, loading/empty/error states, and retained
  form inputs after failed saves. There is no browser persistence fallback.
- CI checks frontend formatting/lint/types/tests/build and Rust formatting/tests/
  Clippy. Desktop jobs request AppImage/deb, NSIS exe/MSI, and separate macOS
  Intel and Apple Silicon app/DMG builds and upload artifacts. Tagged releases
  reuse those checks and prepare a draft release. No ordinary CI signing secrets.
- All requested open-source documentation and Apache-2.0 licensing.

## Architecture decisions

UI features → Zustand → typed Tauri IPC → Rust command handlers → validated
domain services → SQLite repositories. The service owns transactional writes;
the repository owns connection setup, migrations, and snapshot queries.
One mutex-protected connection serializes the small M01 workload. The active
workspace belongs in SQLite rather than browser storage; appearance is only a
local WebView preference.

SQLite is bundled with rusqlite, avoiding a separate database install. Desktop
is the default Rust feature; disabling default features permits the same real
services/database tests to run without WebKit/GTK. No filesystem, shell, SQL,
HTTP, or opener plugins are exposed to React. Capabilities grant no core/plugin
permissions; the app uses the native window frame. CSP restricts resources and
IPC. Further details are in docs/ARCHITECTURE.md.

### Native runtime check

The real native executable opened in the available Wayland desktop. Using
`wtype` keyboard input through the actual forms:

1. Created **Forma Studio** and verified its UUID/name in SQLite.
2. Created **Forma Desktop**, edited it to **Forma M01**, and saved the description
   **A reliable, local-first desktop foundation.**
3. Stopped the process and launched the same executable again.
4. Inspected the rendered native UI: workspace selection, project name, and
   description were restored.
5. Queried the actual runtime SQLite database: same UUIDs/selection and edited
   description; `PRAGMA integrity_check` returned `ok`, and
   `PRAGMA foreign_key_check` returned no violations.

The full desktop Rust test suite also passed with dist temporarily absent,
matching CI where frontend build output is not shared between jobs.

The runtime used isolated data/config/cache directories under /tmp:

```sh
XDG_DATA_HOME=/tmp/forma-runtime-data \
XDG_CONFIG_HOME=/tmp/forma-runtime-config \
XDG_CACHE_HOME=/tmp/forma-runtime-cache \
LD_LIBRARY_PATH=/tmp/forma-sysroot/usr/lib \
src-tauri/target/debug/forma
```

The first launch aborted because the temporary WebKit install still expected
/usr/lib/webkit2gtk-4.1/WebKitNetworkProcess. A temporary mount workaround then
segfaulted in JavaScriptCore initialization (confirmed via coredumpctl; internal
library frames were unsymbolized). That workaround was abandoned. The extracted
WebKit library's two helper-directory strings were redirected to /tmp/fw, a
symlink to the extracted helper directory. The subsequent native launches and
restart succeeded without disabling WebKit sandboxing. These changes exist only
in the temporary third-party library, not in application source or CI.

Diagnostic artifacts are at:

- src-tauri/target/debug/forma
- src-tauri/target/debug/bundle/deb/Forma_0.1.0_amd64.deb
- src-tauri/target/debug/bundle/appimage/Forma_0.1.0_amd64.AppImage

These are debug artifacts built using the temporary dependency environment.
They are not validated portable release installers. Install the documented
normal OS prerequisites and use CI/release builds for distribution.

### Test coverage

Seven Rust tests cover workspace CRUD/selection/deletion fallback; all editable
project fields, CRUD/archive/restore and workspace isolation; reopen persistence;
migration versioning/idempotence/tables and foreign-key cascades; rejected inputs
without writes; rejection of a newer schema; and rollback when activity logging
fails.

Eleven frontend tests cover restoration/retry/structured failures/serialization
in the store; complete project form submission and unsaved-input retention;
workspace creation and rename; cancel/confirm deletion behavior; and persisted
light/dark/system theme resolution.

Initial checks exposed a Rust helper-lifetime error, missing temporary linker
search path, the pnpm esbuild policy, and Node 26's host Web Storage overriding
jsdom. Each was corrected and the relevant checks rerun. scripts/test.mjs passes
the storage-disable option to Vitest and its workers so jsdom provides Storage.

## Known limitations

- Windows exe/MSI and both macOS architectures are configured but unverified here.
  GitHub Actions has not been triggered, and draft release creation has not been
  exercised against GitHub.
- Linux debug bundling succeeded; installer installation, AppImage portability,
  optimized release builds, signing, and notarization were not verified here.
- This machine needs the normal WebKitGTK package installed for a standard
  development launch; native verification used the documented temporary setup.
- Native UI creation/edit/restart was checked directly. Exhaustive native GUI
  automation is not included; other CRUD paths have real SQLite service tests
  plus frontend form/confirmation tests.
- IPC types are maintained manually. One synchronous database connection suits
  M01; large datasets will need background queries/pagination.
- Data is unencrypted, local to one device, and has no export/recovery UI yet.
- Issues/labels/activity have schema foundations but no user-facing editing/feed
  in M01. AI agents, cloud sync, authentication, updater, and telemetry are absent.
- Windows installers are unsigned; macOS CI uses ad-hoc signing and is not
  notarized. README documents trusted-distribution requirements.
