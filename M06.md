# M06 — Multi-Agent Execution & Reliability

Implementation date: 2026-10-15. This report distinguishes local execution from
workflow coverage and unverified native platforms. M05 changes already present in
the working tree were preserved. No commit, push, release or automatic integration
was performed.

## Delivered functionality

- A bounded Rust coordinator with a persisted default-one process budget and an
  explicit maximum of two, shared by agents and independently approved tests.
  Existing immediate approvals remain supported. Per-issue run exclusivity and
  independent cancellation, timeout, progress, logs and review remain intact.
- A persistent approved-task queue with five-minute single-use approvals,
  cancellation, reordering, Start Next, Start Approved Queue and Stop dispatch.
  Dispatch membership is frozen when started; later approvals cannot join it.
  Startup never dispatches; restart/restore invalidates unused approval snapshots.
- Unique UUID branches/worktrees for every run, serialized creation in one
  coordinator and concurrent work on the same or different source repositories.
  The primary working tree is never the provider execution directory.
- Revalidation of task/project context, issue revision, repository authorization,
  common Git directory/HEAD, executable canonical path/SHA-256, advertised CLI
  flags, permission policy and limits. Workers check executable identity again
  before spawn. Cancellation before spawn does not start a process.
- Per-run bounded channels/logs, raw-output accounting before redaction, output
  exhaustion termination, timeout and independently owned process groups/jobs.
  Finished cancellation handles are discarded before new launches.
- Independently approved project tests: native executable authorization, structured
  argument arrays, exact command/cwd preview, separate expiring approval, bounded
  output, timeout, cancellation, duration, exit code and persistent history.
  Neither provider reports nor test exit results automatically mark issues Done.
- Worktree Management with run/issue/repository/branch/path/status, bounded disk
  measurement, identity-checked opening, review/clean-state checks and explicit
  deletion confirmation. Modified, ignored, unreviewed, unknown, locked or
  symlinked content blocks cleanup. Branches/history survive removal. Interrupted
  cleanup has an explicit safe registration-recovery path.
- Append-only migration 006 and format-4/schema-6 backups, with exact released
  format-1/2/3 compatibility in staging. Restored executable/repository/worktree
  authorizations are removed; queue tasks and interrupted tests never replay.
- Preserved four-platform CI matrix, extended frontend checks on every native
  target, simulated native lifecycle/security tests through Rust, and package
  initialization smoke steps. Added `scripts/package-smoke.py`: Windows NSIS
  silent install, Linux deb extraction and macOS DMG mount/copy followed by
  isolated-data process/database initialization checks.

## Architecture changes

UI → feature coordinator → typed IPC → Rust command → validated service → SQLite
repository/provider supervision remains the execution path. No browser/mock
persistence, arbitrary shell command endpoint or new Tauri capability was added.
`execution_service.rs` separates durable approval snapshots from execution and
holds dispatch membership only in memory. `test_execution.rs` shares the process
budget/supervisor but stores independent results. `worktree_service.rs` owns
validated inspection/cleanup. Migration 001–005 contents remain unchanged by M06.

See [MULTI-AGENT](docs/MULTI-AGENT.md) for scheduler lifecycle, concurrency and
recovery invariants, [AGENTS-INTEGRATION](docs/AGENTS-INTEGRATION.md) for provider
policy and [BACKUP](docs/BACKUP.md) for restore/retention operations.

## Performance measurements

Executed:

```sh

```

the same repository, completed in **2.315 s** wall time. Sampled per-leader peak
RSS was **2360 / 2360 KiB**, with **4720 KiB** simultaneous sampled sum. Each
accumulated **198 CPU ticks** at 100 ticks/sec, approximately **1.98 CPU seconds**.
Sampling every 20 ms is a lower bound and excludes Forma, watchdogs and descendant
processes. This is a small fixture measurement, not a real-provider capacity claim
or an enforced CPU/RAM limit. Output-flood tests confirm one run reaches its
bounded failure result while the other remains independently cancellable.

## Security limitations and known issues

Worktrees share Git metadata and are not sandboxes. Providers and approved test
runners run with the current user's privileges; filesystem reads, credentials,
network and repository scripts may remain exposed. A trusted runner can launch
subprocesses. Codex command restrictions and Claude file tools do not isolate the
whole CLI. **Require whole-provider OS isolation** fails closed because this build
cannot enforce it. No provider self-elevation or silent fallback is allowed.

Unix process groups/watchdogs do not contain descendants deliberately escaping
the group; executable/path hashing and cleanup checks cannot remove all same-user
filesystem races. There is no hard CPU/RAM/disk quota. Redaction is heuristic;
backups and logs can contain private task/code data and are not encrypted.
Git diff/status allocations remain proportional to repository metadata. Capability
probes and bounded worktree scans can temporarily delay other service calls.
Disk usage is unavailable for missing/inaccessible/symlinked or >10,000-entry
worktrees. Cleanup deliberately refuses modified/ignored files, even after review;
preserve them manually. Queue responses retain at most 100 rows and run/test
history responses at most 20 rows. Recovery backups require deliberate manual
retention/removal; no automatic deletion policy was introduced.

## Follow-up dispatch recovery

A final review found that a failure during dispatch initialization could retain an
in-memory session with no dispatcher. Queue initialization now releases its
session on error, and the command clears the matching session if the dispatcher
thread cannot be created. Already launched runs remain independent. An injected
SQLite trigger failure proves the task stays Approved, no run starts, the dead
session is gone, and a subsequent explicit Start succeeds after the fault is
removed. The focused `cargo test --locked --manifest-path src-tauri/Cargo.toml
--no-default-features failed_dispatch_releases_session_for_explicit_retry` passed.
The IPC transport test also launches Start Approved Queue through its actual
thread-owning command and observes completion. The full Rust/IPC suites and Clippy
were rerun for this change; current counts
are recorded in the command table. The success-path UI is unchanged.
