## Journey audit and delivered changes

M08 sent an already authorized/signed-in user through installation and sign-in
pages, required Continue after folder selection, repeated a generic permission
acknowledgement, and added a readiness page before exact task preview. Settings-
first setup also required returning to the saved issue for repository connection.

M09 starts from **Run with AI** in the saved issue. **Find installation** routes
to the next missing requirement; authorization advances after existing identity,
capability and sign-in checks. Completed installation/sign-in pages are skipped,
and native folder selection advances directly to permission review. Review opens
the existing exact task preview. The redundant generic acknowledgement and separate
readiness page are removed. Executable authorization, Claude's separate per-run
host-risk consent and final single-use execution approval remain required.
**Back** still lets users inspect earlier requirements and provider login.

The visible summary shows **Installed**, **Signed in**, **Repository connected**
and **Ready to run**. Readiness means ready for approval, not guaranteed credits,
network access or repository eligibility: preview revalidates the canonical
executable, repository/HEAD, settings and saved issue. Settings-only completion
explicitly directs the user to a saved issue for its folder and task preview.

Installation help expands automatically when no candidate is found. Paths and trust
authorization remain visible; SHA-256, prerequisite checks and technical diagnostics
are optional details. Plain-language step names replace internal state names.
Successful explicitly initiated browser login triggers an automatic status recheck;
failed/cancelled or unknown status retains explicit retry and never implies readiness.
The fixed documented `codex login` / `codex login status` and `claude auth login` /
`claude auth status` interfaces were rechecked against [official OpenAI commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
and the [Claude CLI reference](https://code.claude.com/docs/en/cli-reference).
No login output, device code or credential input is collected by Forma.

Known native locations and the absolute Codex installation-directory override are
reserved before bounded PATH scanning. Duplicate directories no longer consume
the scan budget. This finds standard new installations without waiting for a new
GUI PATH; arbitrary inherited PATH changes still need restart or the native picker.
Discovery reads metadata/bytes, never executes candidates or package managers.
Authorization still binds a five-minute scan token to provider/canonical path/SHA-256
and repeats existing identity and capability checks. No installer is run by Forma.

## Measurement method and actual timings

Test-only `onboarding_metrics.py` records instrumented action counts, elapsed time,
errors/recoveries and seven allowlisted stages. Metrics contain no prompt, account,
path, login output or credentials. There is no production telemetry or new database
state. Screenshots/native logs remain in local temporary directories; CI uploads
numeric onboarding evidence alongside existing sample-only package diagnostics.

Counters cover instrumented clicks/form fills, excluding keyboard submissions,
native picker keystrokes, polling and some direct accessibility actions. They are
harness counts, not exhaustive human click totals. Python uses a monotonic clock;
Swift/PowerShell stage timers use elapsed host-clock values. Times include waits,
status/identity checks and dialogs; Windows/Mac times exclude interpreter startup.
These are coarse test diagnostics, not human usability studies, clean benchmarks
or cross-platform speed rankings.

## Security and remaining friction

UI → coordinator/store → typed IPC → Rust command/service → repository/SQLite is
preserved. There are no migration, dependency/lockfile, CSP or capability changes;
no general shell/filesystem/opener IPC, credential persistence, automatic installer
or silent agent launch. Explicit executable authorization, exact single-use prompt
approval, launch-time identity/HEAD/settings revalidation and Claude's separate
host-risk consent remain authoritative. Recommended configuration preserves required
whole-provider OS isolation and fails closed when unavailable. No automatic commit,
merge, push or integration was introduced.

Authenticated inference is verified on Linux only. Windows and both Mac native
flows use a simulated CLI; real Windows/macOS provider inference, actual browser-
login completion, different GUI-launcher PATHs, missing-runtime/offline installation
and consumer signing/trust remain unverified. Native installation stays manual;
wrapper-only/custom installations can require the native picker or restart.
Unknown CLI/auth interfaces fail closed. Dirty/unborn/detached/submodule/tracked-
symlink repositories still require user preparation, and interactive provider login
fallback still belongs in the provider's terminal flow.

Next steps: investigate the intermittent Linux package-harness input mismatch;
run human first-user studies; investigate redundant informational discovery hashing without dropping
mandatory launch-time checks; improve documented interactive login handoff; and
retain the separate M07 signing/trust and whole-provider containment work. No
release or merge to main is part of M09.
